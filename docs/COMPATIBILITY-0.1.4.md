# 随屏 · TaskbarFollow

**0.1.4 试用版 · Windows 11 x64 · 2026-11-09**

从哪一块屏幕的任务栏点击应用，就尝试把这次激活的应用窗口带到那块屏幕。
核心为 **AutoHotkey v2 + Windows API / UI Automation**。已附官方便携运行时，不必安装 AutoHotkey。

> 这是“真实任务栏点击确认 + 应用身份关联 + 激活后迁移”，不是“鼠标在哪，所有前台窗口就跟到哪”。
> 新应用可能先在旧屏出现一瞬，再迁移；本程序不能保证它从第一帧就创建在目标屏幕。

## 1. 怎么开始

1. 保持整个文件夹完整，双击 **`Start.exe`**。如果该启动器受系统策略限制，可尝试 **`Start.cmd`**。
2. 启动后会立即弹出 **“随屏 · 运行状态”** 窗口：识别器真正连接后显示绿色 **“运行中”**，同时显示显示器数量、最近处理反馈和已确认迁移次数。初始化、暂停、识别器断开会显示各自真实状态。
3. 用另一块屏幕的任务栏点击一个已打开的应用，检查窗口是否跟过来。
4. 窗口里可直接暂停/启用、查看日志、生成诊断、收起到托盘或退出。`Ctrl + Alt + F12` 仍可切换启用/暂停。
5. **关闭窗口的 × 只是收起，不是退出。** 再次双击桌面“随屏 - 多屏窗口跟随”快捷方式或 Start.exe，会显示已有窗口，不重复启动/重启；彻底停止请点 **“退出程序”**。

默认**不开机自启、不申请管理员、不改 Windows 显示设置、不安装服务**。
需要自启时，由你在托盘中勾选“开机启动（当前用户）”；取消勾选会删除该启动快捷方式。
移走程序文件夹前，请先取消自启；所有文件应始终放在一起。

如果任务栏只显示在主屏，那么点击位置自然只在主屏。本次对这台电脑的只读检查已发现主、副两个任务栏。

0.1.2 补齐了快速重复启动的实例交接、最小化后重新唤出，以及迁移失败的可见反馈；已在实际桌面验证关闭收起、最小化和再次启动。

0.1.3 修正了会阻断实际跟随的鼠标坐标错误：任务栏点击、释放与拖动判定统一读取原生物理屏幕坐标，不再随着前台窗口变化而改变坐标原点。此前“运行中”和隔离窗口测试通过，并不能证明真实任务栏点击可以跟随。

0.1.4 修正了启动期间丢弃点击的缺口：状态窗口显示前先安装输入监听；应用映射或识别器尚未就绪时，保留最近一次有效任务栏点击，在原有等待时限内继续处理。新增初始化耗时及迁移耗时日志。任务栏分组预览改用原生类名枚举，避免普通窗口列表漏掉可见预览；展开分组时会提示选择具体窗口。这些修复不代表已经确认了 11 月 9 日首次点击失败的唯一原因，也不改变本版激活后迁移的技术路线。

## 2. 默认交互

| 操作 | 本程序的处理 |
| --- | --- |
| 点击任务栏里的应用图标 | UIA 确认应用按钮，再等待与该应用身份一致的前台窗口；只迁移这个窗口 |
| 已最小化应用正常被任务栏恢复 | 恢复之后迁移，普通/最大化状态分别处理 |
| 在另一屏点击**当前已经是前台**的应用 | 默认把它带过来，不让原生“点击当前应用最小化”阻碍跨屏；可以在配置里关闭这一例外 |
| 在窗口已经所在的同一屏点击其任务栏图标 | 不迁移，保留系统原生最小化/恢复行为 |
| 点击分组图标出现缩略图 | 不提前搬组内某个窗口；等待实际选择缩略图 |
| 点击原生缩略图 | 仅当 UIA 暴露可精确匹配、且唯一的窗口标题，并且该窗口实际成为前台时迁移；无法确认则跳过 |
| 点击开始、搜索、小组件、任务视图、托盘、任务栏空白 | 不迁移 |
| Alt+Tab、Win+数字、Shift/Ctrl 等修饰键点击、中键/跳转列表、搜索启动、桌面快捷方式、普通窗口切换 | 不触发跟随；这是本版的明确范围 |
| 点击后把鼠标移到另一屏 | 仍以**点击发生时的屏幕**为目标，不追逐后续鼠标位置 |
| 点击后又点击别处、按键、暂停或更改显示器配置 | 取消尚未完成的操作及短期重试 |

不拦截/重放任务栏鼠标点击，不注入 Explorer，不修改系统任务栏文件。

## 3. Windows 的“根据显示器连接记住窗口位置”要不要关？

**先保持勾选，不需要为了本程序关闭。**

本程序采取的是事件边界隔离，而不是与 Windows 的位置记忆功能长期争夺窗口：

- 没有明确的任务栏应用点击，就不主动迁移窗口；单纯焦点变化不会触发。
- 插拔显示器、改变分辨率/工作区、系统挂起/恢复、Explorer 重建任务栏时，取消当前事务并冷却约 1.8 秒，让系统先处理布局恢复。
- 目标显示器、分辨率和工作区会再次核验；点击时的目标已变化则放弃。
- 激活后只做短期收尾：最多 3 次迁移请求，整个收尾不超过约 1.4 秒；新输入或切走焦点立即终止。
- 不读取或写入这个 Windows 选项的注册表值，不把它当作运行前提，不做持续锁屏/窗口钉屏。

这不等于能保证“永不冲突”：应用自身也可能保存并延迟还原位置。持续强制恢复位置的应用，本程序会放弃，不会一直拉扯。
你主动迁移后的新位置也可能成为 Windows/应用下一次记忆的位置，这属于正常结果，并非保存了两套互不影响的位置历史。

## 4. 兼容边界——请先了解

- **定位后迁移，不是拦截窗口创建。** 冷启动可能有短暂闪现；默认等待 8 秒，超过后不再追认。
- 快速连续启动多个应用时只保留最后一次点击事务；为避免误搬，可能放弃早先仍在启动的应用。
- Windows 11 任务栏的 UIA peer 类名和 AutomationId 是实际观测的壳实现，**并非微软承诺永久稳定的任务栏接口**。系统更新、第三方任务栏、自动隐藏时序，都可能导致漏判。本版遇到不认识的结构会跳过，不退回“坐标 + 焦点”的猜测方案。
- 应用身份依次使用窗口/打包应用 AppUserModelID、完整路径、固定/开始菜单快捷方式中的 AppID 对应可执行文件，以及明确配置的映射。进程级桌面 AppID 不总有可用的受支持远程查询途径，因此没有通吃所有应用的保证。
- 显式 AppID 不一致时**不会**再按同名进程强行匹配。多个浏览器配置、PWA、Squirrel/更新器代理、多个相同可执行文件对应不同任务栏组，可能无法安全区分。
- 快捷方式自动映射只接受本地、目标存在、无参数的 exe 快捷方式；有歧义则跳过。映射在启动时读取，修改固定项/安装路径后请重启。
- 默认额外提供已核验名称的飞书映射 `com.electron.Feishu=Feishu.exe`，用于其版本目录/启动器场景。这仍不是对飞书所有版本的兼容承诺。
- 缩略图标题重复、没有无障碍标题、关闭按钮、未知预览实现：保守跳过；不会把整组窗口搬走。
- 普通窗口、最大化窗口有原生 API 测试；贴靠分组/FancyZones 的分组关系、应用自定义布局，不保证保留。
- 采用每线程 Per-Monitor V2 感知和物理坐标，处理负坐标、不同尺寸及工作区；跨屏 DPI 变化交给 Windows/应用处理。**不保证所有老程序/混合缩放下的视觉尺寸完全相同。**
- 排除工具窗口、隐藏/禁用/无响应/被虚拟桌面遮蔽的窗口、常见无边框全屏、非独立拥有者对话框。游戏独占全屏不在支持范围内。
- 普通权限程序对管理员权限窗口可能无权迁移；不自动提权。需要时先评估是否信任本程序，再自行以相应权限启动。
- 仅本机交互桌面、Windows 11 64 位作为本次目标；没有宣称支持 Windows 10、所有 Windows 11 更新或所有远程桌面场景。

## 5. 配置与诊断

修改 `settings.ini` 后，先退出，再重新双击 `Start.exe`。

```ini
[General]
Enabled=1
BringActiveAcrossMonitors=1
ActivationTimeoutMs=8000
StableDelayMs=180

[AppIdMap]
Microsoft.Windows.Explorer=explorer.exe
Chrome=chrome.exe
MSEdge=msedge.exe
com.electron.Feishu=Feishu.exe
```

`BringActiveAcrossMonitors=0`：完全保留系统对已激活任务栏图标的最小化行为。再次点击恢复时再跟随。

**某个应用不动时：**

1. 确认不是全屏/管理员窗口/模态对话框，托盘状态为“已启用”。
2. 托盘 →“生成兼容性诊断（只读）”。报告保存为 `diagnostics.txt` 并用记事本打开。
3. `[HIT OK]` 表示按钮命中通过，不代表已经做过应用点击端到端测试；0 个匹配也可能只是应用尚未启动。
4. 若窗口没有显式 AppID，可按报告中的 AutomationId，在 `[AppIdMap]` 增加准确 exe 名或完整路径；优先完整路径。不要给有不同配置/组的浏览器盲加宽泛进程映射。
5. 日志位于 `logs\TaskbarFollow.log`，大小上限约 1 MiB，另保留一份轮转文件；`requested` 仅表示 API 请求已提交，不等于应用最终接受了位置。

诊断不点击、不激活、不移动你的应用。默认日志不记录按键内容或窗口标题；应用 ID 本身可能包含路径，分享日志前请自行检查个人信息。
运行期没有账号、服务器或遥测功能；读取本机快捷方式只是为了识别应用，不执行快捷方式。

## 7. 源码、测试和第三方来源

- `TaskbarFollow.ahk`：托盘、输入边界、点击事务、前台事件、超时/拓扑变化、短期收尾。
- `Probe.ahk` + `lib\UIA.ahk`：独立进程中的任务栏语义命中；UIA 卡住不会把主进程/鼠标回调卡在 COM 调用里。
- `lib\Native.ahk`：显示器、应用身份、工作区坐标转换、窗口迁移。
- `lib\Policy.ahk`：可单测的状态/安全规则。
- `lib\StatusWindow.ahk`：可见状态窗口，显示真实识别器连接状态、暂停/启用、处理反馈。
- `lib\Instance.ahk`：重复启动唤出已有窗口；测试模式独立隔离，不会停止你的运行实例。
- `launcher\Launcher.cs`：仅用于便携启动的极小 .NET Framework 启动器，核心逻辑不在 C#。
- `runtime\AutoHotkey64.exe`：官方 v2.0.31 便携运行时；许可证见同目录及 `third-party`，对应上游源码压缩包也已附上。

开发测试命令（会创建自己的测试窗口，建议空闲时运行；不迁移用户应用）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1
```

这里的执行策略参数仅针对该次 PowerShell 进程，不是修改系统的永久执行策略。
程序及启动器未代码签名；如系统安全策略拦截，请先核验来源/源码，不要关闭系统安全软件。

实际桌面回归测试单独放在 `tests\Run-LiveTaskbar.ps1`，通过 `tools\Invoke-InputDesktop.ps1` 运行在输入桌面，不会随默认测试运行。`-Case cursor` 创建两个临时测试窗口，检查焦点切换前后坐标；`-Case fixture` 创建独立任务栏身份的临时窗口，验证主屏最小化、副屏实际点击恢复和迁移，完成后销毁测试窗口；`-Case edge` 真实点击副屏 Edge 图标，要求开始时没有 Edge 应用窗口；`-Case code` 会临时最小化现有 VS Code 窗口并从副屏任务栏恢复。后两种测试会操作鼠标和真实应用窗口，应在空闲时明确选择运行；VS Code 测试成功或失败后均恢复原布局，选择缩略图前检测到其他鼠标输入会中止测试。
