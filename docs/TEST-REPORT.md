## 用户操作验收清单（尚未完成，建议按顺序）

保留“根据显示器连接记住窗口位置”的勾选，双击 Start.exe 后：

1. **已打开的普通窗口**：将 Chrome/记事本放在 A 屏，在 B 屏任务栏点击；应到 B。再从 A 屏点回。
2. **最小化恢复**：在 A 屏最小化后，从 B 屏任务栏恢复；应恢复在 B。
3. **最大化**：A 屏最大化，从 B 屏任务栏激活；应在 B 仍最大化，之后手动还原检查尺寸/位置是否合理。
4. **已处于前台但在另一屏**：从 B 屏点其任务栏图标，默认应带到 B；设 BringActiveAcrossMonitors=0 后应保留原生最小化行为。
5. **同屏最小化**：窗口在 B 时再点 B 屏对应图标；应保持系统原生最小化，不被抢回。
6. **冷启动**：关闭某应用，鼠标在 B 屏点击任务栏固定项；允许先在 A 闪现，再在 8 秒内迁移到 B；超过后不应很久之后突然搬动。
7. **分组缩略图**：打开多个标题不同的窗口；只点图标打开预览时不应迁移，选择某张缩略图后仅该窗口迁移。标题相同/识别不清时允许保守不动。
8. **负例**：开始、搜索、托盘、任务视图、任务栏空白、右键、中键、修饰键点击、图标拖动、Alt+Tab，不应触发搬窗。
9. **快速切换/取消**：点慢启动应用后立刻操作另一窗口、输入或切屏；不得稍后搬动无关窗口。
10. **多 DPI**：各屏不同缩放下反复迁移普通/最大化窗口，检查可见性；不以“逻辑尺寸绝对一致”为通过标准。
11. **连接记忆**：应用分别放两屏，拔插/休眠唤醒；不点任务栏时应让 Windows 自行恢复。恢复完成后再点击，跟随才生效。
12. **应用自身恢复位置**：检查飞书、浏览器配置、PWA 等。若窗口来回抢位置，程序应在约 1.4 秒/3 次请求内放弃，并能由新输入立即停止，不持续争抢。
13. **退出与自启**：托盘退出应结束主/辅助两个进程；只有手动勾选自启后才创建当前用户启动快捷方式。

未完成这些实际操作前，版本定位为**可运行试用版**，不是全面验证过的生产工具。

## 0.1.3：真实任务栏失败的排查

用户反馈：VS Code 在主屏最小化后，从副屏任务栏恢复仍在主屏；没有窗口的 Edge 从副屏任务栏启动也仍在主屏。先前的隔离测试和状态窗口验证没有覆盖这条真实输入路径，因此不能作为核心功能有效的证明。

- 实际日志中这几次点击均为 `transaction end: taskbar-drag`，没有进入应用确认或窗口迁移。
- 原因：MouseGetPos 默认返回前台窗口客户区坐标，而程序把它当作物理屏幕坐标用于 UIA 命中、显示器选择、按下/释放差值和拖动判定。焦点变化会改变客户区原点，导致误判拖动或命中错误位置。
- 修复：增加 `Desktop.Cursor`，统一使用 Windows `GetPhysicalCursorPos`。读取失败就取消事务；状态页在无输入桌面访问权的隔离测试中使用自身窗口所在屏幕定位。
- 新增真实输入回归：固定鼠标、切换两个不同位置的临时窗口。旧客户区坐标变化 `-600,-200`，新物理坐标变化 `0,0`，已重现并验证根因。临时窗口随后销毁。
- Edge 实际任务栏验证：开始时没有符合资格的 Edge 窗口（后台进程仍存在）；在副屏物理坐标 `4550,2124` 点击 MSEdge 按钮。新窗口先出现在 `DISPLAY1`，程序随后将它移到 `DISPLAY5`，并在目标屏幕稳定至少 1.7 秒。测试输出为 PASS，日志包含应用确认及迁移请求。
- VS Code 分组测试必须核对 Windows 实际选择的窗口。现场自动测试受到其他鼠标输入中断，脚本输出 FAIL 并恢复测试前布局；未将它记录为通过。修复后日志确有 VS Code 任务栏和缩略图激活后的迁移记录，但用户答复尚未重新测试，因此仍需实际工作流复核。
- 临时窗口的真实任务栏完整回归：窗口写入独立 AppID `TaskbarFollow.InputRegression`，在主屏 `DISPLAY1` 最小化后，从副屏 `DISPLAY5` 的原生任务栏实际点击恢复。正在运行的正式引擎通过 UIA 确认身份并迁移，测试单独核对同一个 HWND 已恢复、位于目标屏幕且稳定超过 1.7 秒，结果 PASS。全部临时窗口随后销毁，没有用测试代码代替引擎迁移。
- 重新运行默认 8 组测试，全部通过；启动器及 staging 配置检查通过。当前实际桌面实例为 v0.1.3。
- 新增可显式运行的 `tests\LiveTaskbar.ahk`、`tests\TaskbarInput.ahk` 和 `tests\Run-LiveTaskbar.ps1`；不会在默认隔离测试中操作用户应用。发现其他鼠标输入时中止 VS Code 现场测试。

官方 API 依据：[AutoHotkey MouseGetPos](https://github.com/AutoHotkey/AutoHotkeyDocs/blob/v2/docs/lib/MouseGetPos.htm)、[Windows GetPhysicalCursorPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getphysicalcursorpos)。

## 0.2.0：原生显示前定位路线

- 按用户要求替换核心路线。AHK 保留状态窗口与身份缓存；C++ 独立输入线程记录原始物理点击，`WH_CBT` 在创建、恢复、激活前处理目标位置。原生模式不运行兼容模式的延迟迁移。
- 原生 DLL 和测试程序使用本机 Visual C++ / Windows SDK 编译，开启 `/W4 /WX`。便携运行不要求安装编译器。
- 独立进程测试在普通用户权限下，使用单独创建的 Windows 桌面，目标只限测试可执行文件：冷启动且应用再次提交旧屏位置、普通恢复、最大化恢复、暂停、取消、超时，共 6 个显示场景；还覆盖目标应用保持打开时停止/重启控制器、测试接口拒绝其他应用路径。
- 三个正向显示场景均检查第一次可见绘制的显示器，旧屏绘制计数为 0；最大化状态保留。暂停、取消和超时保留原生位置。
- 发现工具沙箱允许钩子安装，但未把 DLL 加载进测试子进程；同一二进制在沙箱外通过跨进程测试。该结果按环境限制处理，没有把沙箱内失败记成通过，也未降级为后移窗口来让测试过关。
